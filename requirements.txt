# Training dependencies -- this is all a GPU pod needs.
#
# IMPORTANT: install torch FIRST, matching the pod's CUDA version, then run
# this file. Most GPU images already ship a CUDA-enabled torch, in which case
# `pip install -r requirements.txt` will simply leave it alone.
#
#   # CUDA 12.1 example -- check `nvidia-smi` for the driver's CUDA version
#   pip install torch --index-url https://download.pytorch.org/whl/cu121
#   pip install -r requirements.txt
#
# torch is left unpinned on purpose: pinning an exact version here fights the
# pod's preinstalled CUDA build and can silently drag in a CPU-only wheel.
#
# The >=2.3 floor is load-bearing, not aspirational. train.py builds its scaler as
# `amp.GradScaler(device=DEVICE.type)`, and the unified `torch.amp.GradScaler`
# only landed in 2.3 -- in 2.2 that name does not exist under torch.amp at all
# (there is only `torch.cuda.amp.GradScaler`, which takes no `device`). On 2.2 a
# run therefore dies at startup, AFTER the dataset scan, which is the slow part.
torch>=2.3
numpy>=1.24
